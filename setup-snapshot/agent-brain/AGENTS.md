# Park's knowledge map

This is a small, local Markdown knowledge base. Read the relevant card, then verify changing facts against the project or live service. Do not load the whole tree into every conversation.

- `MEMORY.md`: stable preferences explicitly stated by Park.
- `projects/`: pointers to canonical project records, current handoffs, and open decisions. Project repositories remain authoritative.
- `notes/`: one evidence-backed topic per file, including workflow lessons.
- `people/`: public source/author cards; no invented personal relationships.
- `LEARNINGS.md`: observed failures, the fix at its proper level, and the check that supports it.
- `decisions.md`: consequential setup choices, reasons, and rollback pointers.
- `runs/`: concise run receipts and the generated local health report.
- `templates/`: briefs and receipts to copy for actual work.

Use lowercase, hyphenated filenames. Keep one topic per file, date time-sensitive claims, and link the primary source or actual artifact. Mark proposals, observations, and unresolved questions explicitly. Update an existing topic instead of making duplicate summaries. Keep secrets and full private transcripts out of this tree.

On a handoff, preserve the intended outcome, verified state, decisions, exact process/job handles, remaining work, and next executable action. A stale note never proves a process is alive. On retrieval, report a missing fact instead of filling the gap from inference.
