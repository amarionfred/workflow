---
name: production-handoff
description: Scope a game-development workstream and preserve decisions, evidence, dependencies, and next actions across separate Codex chats.
---

Read the project's START-HERE, STATUS, and decision register. Distinguish confirmed user direction, proposed direction, technical observations, and unknowns. Do not promote a previous assistant's suggestion into a user decision.

Define one bounded deliverable with inputs, dependent workstreams, acceptance evidence, and exclusions needed to avoid accidental scope expansion. Prefer an end-to-end playable slice when uncertainty crosses multiple disciplines. A long list of individually finished systems is not proof they work together.

Maintain a source-of-truth map for code, Studio place, environment source, exports, narrative data, and external assets. Record versions and hashes where they affect reproducibility. Store source links and timestamped observations separately from interpretations. A downloaded catalogue is not a watched catalogue.

End a work session with changes, verification, unresolved problems, current process state, and the next executable action. Reference files rather than pasting the whole research library into every new chat. Update the decision register only when a decision actually changes.

Skills and plugins provide procedures and tool access; they do not confer studio staffing, original performance capture, production experience, or guaranteed AAA output. Assess quality through the delivered scene and player evidence.

Deliver a workstream brief and a short new-chat prompt that names the workspace, desired result, and relevant references. Never declare the entire project complete because one milestone is ready.
