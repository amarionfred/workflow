# Codex compatibility for pstack

This is a local adaptation of Lauren Tan's MIT-licensed pstack. The unchanged source is pinned in `PROVENANCE.json` and `/home/park/Projects/agentic-workflow/vendor/cursor-plugins/pstack`. Preserve its engineering methods; apply the following translations where upstream assumes Cursor infrastructure.

- Use the current user's instructions and existing authorization. A skill does not authorize messages, purchases, merges, deployment, or broader access by itself. Carry out already authorized work without asking again.
- `/name` in upstream prose means the bundled skill at `skills/name/SKILL.md`. In Codex, select the installed skill in the UI or invoke its displayed `$` name. A Cursor slash command does not become a Codex command by installation.
- `Task` means a bounded `collaboration.spawn_agent` when available and allowed. `subagent_type` names are prompt templates, not supported parameters: read `agents/poteto-agent.md` or the specified reference and include its relevant instructions. Respect live concurrency limits. Use independent worktrees for concurrent writes to the same repository.
- Read `~/.config/agentic-workflow/pstack-models.md` for role defaults. All roles inherit the parent model and reasoning by default. Upstream Grok/Claude slugs and model-speed suffixes are examples for Cursor, not callable Codex models. Never silently claim cross-model diversity. If diversity is needed, use only models exposed by the current tool and permitted by the user's choice; otherwise report that the reviewers share a model family.
- `AskQuestion` maps to an available user-input tool, or a concise question when necessary. Do not repeat setup questions already answered by the user or local configuration. `TodoWrite` maps to the available plan tool or a short task file. `Read`, `Grep`, and `Shell` map to file reads, `rg`, and the shell tools.
- Use Codex's `skill-creator` for skill authoring. `deslop` is optional when unavailable: inspect the diff with `unslop`, `no-comments`, and actual repository checks. `control-cli`/`control-ui` require a real control tool: use the available PTY, Playwright/browser, or project adapter and capture observable evidence. Never claim a missing control skill was executed.
- `/goal` is Codex's persistent goal feature where available. Set a goal only at the user's request. Cursor `/loop`, cloud-agent, Slack, webhook, and scheduling services are not installed by this port. Use an actual available scheduler/runtime; distinguish saved procedures from running jobs. A local process cannot work while its computer is off.
- For `recall`, `reflect`, `correct`, and `automate-me`, use the current conversation and the indexed knowledge base at `/home/park/Documents/agent-brain/AGENTS.md`. If historical transcript evidence is needed, select only the relevant thread/workspace from Codex's session index; never dump unrelated conversations or credentials. Cursor transcript paths do not apply.
- `setup-pstack` writes the Markdown model mapping above, not Cursor rules. Preserve the configured `inherit-parent` default unless the user asks for a different allocation. Do not ask them to reconfirm that default. Codex discovers user skills in `~/.codex/skills` and project skills in `.agents/skills`; this plugin's skills are resolved relative to its installed root.
- Benny includes all three original workflows and their templates. Its Cursor-specific automation setup is a reference implementation. For Codex, choose a real configured scheduler and tracker, write the equivalent prompt, run a controlled trial, and record its actual service/job handle before calling it enabled. Retain template paths relative to `automations/benny`. Do not write `.cursor/settings.json` for a Codex-only project.
- The two upstream agent files remain templates. This port does not pretend they are separately registered Codex agent types. Shared files are not an isolation boundary for blind evaluations.
- New project work follows that project's `AGENTS.md`, resource limits, and verification surface. Do not manufacture a PR for a local-only task. Research conclusions require raw results, controls, and the existing research review skills, not merely engineering tests or reviewer agreement.

The 54 core skills and 3 Benny skills are all included. Private company skills mentioned by upstream are dependencies or examples, not public artifacts claimed as installed.
